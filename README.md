# 스터디온 · UI/UX 중간 프로토타입

## 7주차에서 새로 추가한 기능

7주차의 **시작 → 입력·선택 → 확인 → 계획 확정** 흐름 끝에 **내 계획에 보관 → 목록에서 다시 열기 → 학습 완료 기록** 경로를 추가했습니다. 확정한 계획을 브라우저에 보관하고, 이후 방문에서 다시 열어 완료 여부를 관리하거나 삭제를 취소·확정할 수 있도록 구현했습니다.

기존 7주차 저장소의 `index.html`, `style.css`, `script.js`를 이어서 수정했습니다. 기준 커밋은 `80a0d06`이며 기존의 입력 검증, 이전 단계 값 유지, 다시 시작, 학습 도구 탭을 유지했습니다. 발표 훈련 예제가 아닌 직접 기획한 **온라인 대학생 학습 계획 서비스**입니다.

## 서비스·사용자·목표

| 항목 | 정의 |
| --- | --- |
| 주요 사용자 | 일과 학업을 병행하는 온라인 대학생 |
| 사용자 목적 | 짧은 학습 시간에 실천할 목표를 정하고, 다음 방문에도 계획을 찾아 실천 여부를 관리하기 |
| 주요 행동 | 과목·목표·하루 시간 입력 → 내용 확인 → 확정 → 보관 → 다시 열기 → 학습 완료 표시 |
| 새 기능이 필요한 이유 | 7주차에는 확정한 계획을 다시 방문해 확인할 수 없었습니다. 보관함을 추가해 계획 수립이 실제 학습과 완료 기록으로 이어지도록 했습니다. |

화면은 서비스 소개, 주요 기능, 이용 방법, 학습 준비 도구, 계획 만들기, 내 계획 보관함 순서입니다. 상단 메뉴에서 계획 만들기와 보관함으로 바로 이동합니다. 보관함에 과목, 목표, 학습 시간, 상태를 표시해 다음 행동을 결정하도록 했습니다.

## 새로운 사용 경로

1. 기존 흐름에서 과목·목표·시간을 입력하고 계획을 확정합니다.
2. 완료 화면의 **내 계획에 보관**을 누릅니다.
3. 보관 성공 안내와 **보관한 계획 열기** 버튼이 나타납니다.
4. 보관함에서 **계획 다시 열기**로 목표와 시간을 확인합니다.
5. 목표를 실천했다면 **학습 완료로 표시**를 누릅니다.
6. 목록으로 돌아가 다음 계획을 선택합니다. 잘못 표시했다면 **학습 예정으로 되돌리기**를 누릅니다.

입력 확인을 반복하는 대신 **확정 결과를 목록의 데이터로 추가하고, 다시 불러온 데이터의 학습 상태를 변경하는 후속 행동**을 구현했습니다.

## 행동 → 조건 → 화면 반응 → 다음 행동

| 사용자 행동 | 확인할 조건 | 성공·다른 분기의 반응 | 다음 행동 |
| --- | --- | --- | --- |
| 내 계획에 보관 | 확정된 계획 존재, 동일 내용 없음, 30개 미만 | 목록 추가, 보관 완료 안내, 연속 클릭 방지 | 보관한 계획 열기 |
| 같은 계획 재보관 | 과목·목표·시간·이메일이 기존 기록과 같은지 | 중복 추가 없이 기존 계획 안내 | 기존 계획 열기 |
| 보관 시도 | 브라우저 저장 가능 여부 | 실패하면 입력과 기존 목록 유지. 저장 공간·사이트 저장 허용 확인 안내 | 같은 버튼으로 재시도 |
| 보관 시도 | 30개 한도 도달 여부 | 한도와 해결 방법 안내 | 필요 없는 계획 삭제 후 재시도 |
| 계획 다시 열기 | 해당 계획의 존재 여부 | 선택한 값과 상태 표시. 사라졌다면 목록과 안내 표시 | 완료 표시 또는 다른 계획 선택 |
| 학습 완료로 표시 | 계획 존재, 변경 저장 가능 여부 | 예정 → 완료, 배지·버튼·완료 개수 갱신 | 다음 계획 선택 |
| 학습 예정으로 되돌리기 | 완료 상태 여부 | 완료 → 예정, 안내 갱신 | 학습 이어서 진행 |
| 상태 필터 선택 | 해당 상태의 계획 존재 여부 | 목록 또는 결과 없음과 전체 계획 보기 버튼 표시 | 전체 계획 보기 |
| 이 계획 삭제 | 대상 존재 여부 | 계획 이름과 삭제 확인창 표시 | 계획 유지 또는 삭제하기 |
| 계획 유지 / Escape | 삭제 확인창 표시 여부 | 삭제 취소, 내용·상태 유지 | 학습 계속하기 |
| 삭제하기 | 대상 존재, 삭제 저장 성공 여부 | 목록에서 제거. 마지막 항목이면 빈 보관함 안내 | 다른 계획 선택 또는 계획 만들기 |
| 목록으로 돌아가기 | 상세 화면 표시 여부 | 필터와 보관 데이터를 유지해 목록 표시 | 다른 계획 열기 |

입력 단계의 이전 버튼은 입력값을 유지합니다. **다시 시작**은 작성 중인 입력·오류·요약과 연결된 준비 도구만 초기화하고 이미 보관한 계획은 유지합니다. 빈 보관함의 **계획 만들러 가기**는 작성 중인 값이 있으면 그 흐름으로 돌아갑니다.

## 입력·상태·접근성

- 과목과 목표는 공백만 입력할 수 없습니다. 시간은 20·40·60분 중 선택합니다. 이메일은 선택 항목이며 작성한 경우 형식을 검사합니다.
- 레이블과 구체적인 버튼 문구로 행동을 안내하고, 오류 입력에 `aria-invalid`를 지정합니다.
- 색뿐 아니라 문구·배지·버튼 상태로 결과를 표시합니다. 결과에는 `role="status"`, 저장 오류에는 `role="alert"`를 사용합니다.
- 상세 화면과 단계 전환 시 제목으로 초점을 옮깁니다. 삭제 확인창은 **계획 유지**에 기본 초점을 두고 Escape로 취소할 수 있습니다.
- 사용자 입력은 `textContent`로 출력해 HTML로 실행하지 않습니다.

## 데이터 범위

- `localStorage`의 `studyon.midterm.plans.v1`에 최대 30개를 보관합니다.
- 같은 브라우저·같은 사이트에서 다시 불러옵니다. 서버 계정, 기기 간 동기화, 이메일 발송은 구현하지 않았습니다.
